# Yabai OCR

[Português](README.pt-BR.md) | **English**

OCR Japanese reader for **desktop** and **Android**: select any Japanese text on screen — a manga
bubble, a subtitle, a game — and instantly see the reading, the dictionary entry and the translation,
without taking a screenshot or switching windows.

Recognition can run **online** (Google Lens) or **offline** (ML Kit on Android, PP-OCRv6 on desktop
and Android), so the app stays useful without a connection.

## What it does

- **Manual crop** of a screen area with immediate text recognition.
- **Full screen with a picker**: the app marks every bubble/paragraph and you tap the one you want,
  instead of getting the whole page.
- **Hover on desktop**: rest the pointer on Japanese text and the card appears with the word and its
  entry. With a dictionary chosen, the answer comes from it; when it has no entry for the word the app
  says so instead of switching dictionaries on its own.
- **Offline dictionaries** in the Yomitan format (Jitendex, JMdict, KANJIDIC and others), with search
  by term, reading or definition, per-dictionary filter and a preferred order.
- **Furigana**: printed reading preserved, reading generated by the dictionary, or both.
- **Kanji card** with strokes, readings and compounds.
- **Offline translation** of the recognized sentence, plus a button to ask an external AI.
- **Choice of OCR engines**, with an automatic mode and a priority order.

## Requirements

The desktop packages bundle their own JDK 21 runtime and write only under `$HOME`: no root, nothing
in `/usr`, no Java to install.

| system | requirements |
| --- | --- |
| **SteamOS / Steam Deck** | Desktop Mode (KDE Plasma, Wayland). Game Mode is best effort — no hover and no global shortcuts there. FUSE 2 (`libfuse.so.2`) is only needed for the `.AppImage`; the `.tar.gz` needs nothing |
| **Ubuntu 22.04+ / Debian 12+** | Wayland (GNOME or KDE) or X11. FUSE 2 for the AppImage: `libfuse2` up to 22.04, `libfuse2t64` on 24.04+. On GNOME the tray needs `gnome-shell-extension-appindicator` and capture needs `xdg-desktop-portal-gnome` |
| **Other Linux x86_64** | glibc 2.31+, `xdg-desktop-portal` plus its backend (`-kde` or `-gnome`), and a Japanese font (`fc-list :lang=ja`) |
| **Windows 10/11** | the `.exe`/`.msi` from the release; nothing else |
| **Android 8.0+ (API 26)** | `arm64-v8a` APK; overlay and screen-capture permissions granted inside the app |

Building from source needs JDK 17+ and the Gradle wrapper — see [Building](#building).

## Installing

> **Download the latest release files for your OS from the [GitHub Releases page](https://github.com/SorrisoKDente/YabaiOCR/releases/latest).**

### SteamOS / Steam Deck (Desktop Mode)

```bash
mkdir -p ~/Applications
mv ~/Downloads/Yabai_OCR*.AppImage ~/Applications/
chmod +x ~/Applications/Yabai_OCR*.AppImage
~/Applications/Yabai_OCR*.AppImage
```

The app opens on Settings and stays in the tray. **Settings → Integrate with the system** adds it to
the application menu, points the entry at the running AppImage and refreshes the menu index (nothing
is written outside `$HOME`); **Start in the tray at login** enables autostart. No FUSE on the machine? Run the AppImage with `--appimage-extract-and-run`, or use the
`.tar.gz` (`tar -xzf … -C ~/Applications/yabai-ocr`) or the `.deb`. Full guide:
[STEAMOS.md](docs/STEAMOS.md).

**Restart the session once after installing if you turn on Settings → 🖼 Silent capture on KDE.** KWin
refuses its screenshot interface to a program that runs from `/tmp/.mount_*`, which is exactly what
an AppImage does, so every hover would otherwise open the portal permission dialog. That switch
writes `~/.config/environment.d/yabai-ocr.conf` and **the session only reads that file at login** —
one log out and back in, once, not on every launch. Shortcuts, tray, hover and capture through the
portal work as soon as the app starts; only the dialog-free capture waits for the relogin.

### Ubuntu and Debian

```bash
# AppImage
sudo apt install libfuse2t64     # Ubuntu 24.04+; use libfuse2 on 22.04 and older
chmod +x ~/Downloads/Yabai_OCR*.AppImage
mv ~/Downloads/Yabai_OCR*.AppImage ~/Applications/
~/Applications/Yabai_OCR*.AppImage

# or the .deb
sudo apt install ./yabai-ocr_<version>_amd64.deb
```

**On GNOME Wayland, log out and back in after the first launch.** The hover pointer comes from a
Shell extension the app installs and enables itself, and GNOME only loads extensions at session
start; before that relogin the app reports hover as unavailable instead of half-working. The tray
needs `gnome-shell-extension-appindicator`. On **KDE Plasma** (Kubuntu) the session restart is only
needed for the silent-capture switch, exactly as on SteamOS. Capture details and the acceptance
checklist are in [LINUX.md](docs/LINUX.md).

### Windows

Run the `.exe`/`.msi` from the release. Windows SmartScreen may warn about an unsigned installer —
"More info → Run anyway". The installer bundles the runtime; there is no Java prerequisite.

### Android

Install the `arm64-v8a` APK (allow "install unknown apps" for your file manager), grant **overlay**
and **screen capture** when the app asks, pick an OCR engine and tap start. The floating bubble
triggers the capture.

## How to use

**Desktop**

```powershell
.\gradlew.bat :desktop:run
```

The app opens on Settings and stays in the tray. The interface exists in **Portuguese and English**,
chosen in Settings. Default shortcuts (all configurable):

| shortcut | action |
| --- | --- |
| `Ctrl + Shift + O` | full-screen capture with a segment picker |
| `Ctrl + Shift + A` | manual crop |
| `Ctrl + Shift + H` | turns hover on/off |
| `Ctrl + Shift + D` | quick dictionary lookup |
| `Ctrl + Shift + X` | cycles the hover readings |

On multi-monitor setups, Settings lets you choose which monitor the full-screen capture and the
manual crop use: the primary one, a specific monitor, or the one under the pointer when you capture.

Windows whose content does not fit the height — Settings, result, dictionary manager, quick lookup,
license and release notes — show a **scrollbar** on the right, on top of the mouse wheel.

The installed version is shown in **Settings → About**, next to the update check button; in packaged
builds it comes from the build tag (`-PyabaiVersion`), not from a fixed number. When a release is
newer, **📄 Release notes** renders the Markdown published with it, and the check on startup can be
turned off in the same card.

**Updating without a browser.** **⬇️ Download Update** fetches the package itself: on the AppImage the
running file becomes `<name>.old`, the new one takes its place and **Restart now** opens it. On
Android the APK goes through `DownloadManager` into the app's downloads folder and **stops there**:
the app neither installs it nor asks for the «install unknown apps» permission — you open the APK
whenever you want. Outside an AppImage — `gradle run`, an unpacked distribution — the desktop build
does not replace its own installation and opens the release page instead.

**Startup notice.** With «Check for updates when the app starts» on, the desktop opens a window with
the download (and the release notes) as soon as it finds a newer version, even when it started in the
tray; on Android the automatic check shows a dialog with **⬇️ Download**. The same controls stay in
the updates card afterwards.

**Android**: install the APK, grant **overlay** and **screen capture** (MediaProjection), pick an
engine and tap start. The floating bubble triggers the capture.

## OCR engines

| engine | runs on | internet | notes |
| --- | --- | --- | --- |
| **Google Lens** | desktop and Android | yes | best overall accuracy; subject to Google's usage limit |
| **ML Kit (Japanese)** | Android | no | model bundled in the APK, fast, good on printed text |
| **PP-OCRv6_manga** | desktop and Android | no | bubble detector + line reader; ~23 MB downloaded in Settings |

In **Automatic** mode the app walks the priority order you chose and only moves to the next engine
when the previous one returns no text — that is how the offline engine takes over without a
connection.


## Graphics renderer

The desktop app draws its windows with Skiko. The default renderer on Windows is Direct3D, which can
close the app without any error in some drivers. Settings → **Graphics Renderer** chooses another one:
**Automatic** (the system default), **OpenGL** (still uses the graphics card, avoids Direct3D) or
**Software** (CPU, slowest and the most stable). The choice applies the next time the app starts.
The same options are on the command line, for when the packaged app is hard to configure:

```
yabai-ocr --renderer=opengl      # or --renderer=software / --renderer=automatic
```

If a run is closed by that crash, the next start moves one step away from Direct3D on its own — OpenGL
first, software only if that also crashes — and says so in the log. Nothing is permanent: pick
Automatic in Settings to go back.

## Dictionaries

Dictionaries are local, in the [Yomitan](https://github.com/yomidevs/yomitan) format: install them
from the app's catalog or import a ZIP. Nothing you look up leaves the device.

## Building

```powershell
.\gradlew.bat :desktop:run          # runs the desktop app
.\gradlew.bat :desktop:test         # desktop suite
.\gradlew.bat :core:test            # core (pure JVM)
.\gradlew.bat :app:assembleDebug    # debug APK
.\gradlew.bat :app:testDebugUnitTest
```

Desktop packages come from `:desktop:packagePortableTarGz` and `:desktop:packageLinuxAppImage`
(Linux) or from the installer generated by Compose Desktop on Windows. On Linux/macOS the same
commands run with `./gradlew`:

```bash
./gradlew :desktop:run                     # runs the desktop app
./gradlew :desktop:test                    # desktop suite
./gradlew :desktop:packagePortableTarGz    # portable .tar.gz
APPIMAGETOOL=~/appimagetool ./gradlew :desktop:packageLinuxAppImage   # single-file .AppImage
```

If `./gradlew` answers `required file not found` or `$'\r': command not found`, the checkout came
with CRLF line endings: `git checkout -- gradlew desktop/package/linux/build-appimage.sh` fixes it
(the repository's `.gitattributes` keeps both files on LF from then on).
